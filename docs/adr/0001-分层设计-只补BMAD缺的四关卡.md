# ADR 0001: 分层设计——只补 BMAD 缺的四个关卡

- **日期**: 2026-07-24
- **状态**: 已采纳

## 背景

BMAD-METHOD v6 已经提供角色 agent、PRD/story 模板、project-context 生成等能力；Superpowers 提供研发内功（TDD/调试/验证）。如果本模块重复造这些轮子，会增加维护成本且偏离定位。

## 决策

本插件只补 BMAD 缺的乙方↔客户交付环节，共四个差异化关卡：

1. **delivery-client-gate**：客户签字关卡（入口）
2. **delivery-feishu-sync**：飞书任务 SSOT 同步
3. **delivery-eval-loop**：AI 评测内循环
4. **delivery-acceptance-gate**：客户验收关卡（出口）

本插件不重复实现 BMAD/Superpowers 已有能力，同时增加必要的交付编排：

- `delivery-prototype-html`：将 BMAD UX 产物编排为客户签字前的可交互 HTML 演示，不替代 bmad-ux 的设计能力；
- `delivery-sprint-sync`：将飞书执行状态单向镜像到本地，不创建第二个可写状态机。

因此当前插件包含四个乙方交付关卡、一个原型编排能力、一个状态镜像能力和一个入口路由能力。

## 后果

- 正面：保持插件轻量、聚焦差异化价值
- 正面：与 BMAD/Superpowers 生态互补而非竞争
- 风险：依赖基座版本演进，需关注 BMAD API 变化
