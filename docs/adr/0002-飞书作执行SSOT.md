# ADR 0002: 飞书作执行状态唯一真源（SSOT）

- **日期**: 2026-07-24
- **状态**: 已采纳

## 背景

BMAD 的 sprint-status 不作为本地状态写端。执行状态需要在飞书维护，同时保留一个由飞书单向刷新、本地只读的 `sprint-status.yaml` 镜像，供本地流程和 AI 查询。

## 决策

- **需求规格真源 = 本地文档**（SPEC.md / PRD / stories / 客户确认记录）
- **执行状态真源 = 飞书**（通过 feishu-sync 推入和维护）
- 二者不重叠。回读飞书只读状态、绝不覆盖本地需求文档正文
- **不启用 BMAD sprint-status.yaml 作为写端**；允许通过 `delivery-sprint-sync` 从飞书单向刷新本地 `sprint-status.yaml` 只读镜像
- 研发直接在飞书改「阶段状态」字段（待开发/开发中/测试中/已上线/缺陷/优化）

## 后果

- 正面：状态源唯一，团队从飞书看板一眼看全局
- 正面：研发只需改飞书状态，不需额外工具链
- 代价：飞书不可用时状态暂不可查（设计上接受，因为飞书是线上协作工具）
- 代价：飞书 API 能力限制（如无法建清单文件夹、子任务只有一层）需在 skill 文档中标明
