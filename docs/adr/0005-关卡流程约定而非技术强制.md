# ADR 0005: 关卡是流程约定，不设技术强制

- **日期**: 2026-07-24
- **状态**: 已采纳

## 背景

插件所有关卡（client-gate / feishu-sync / eval-loop / acceptance-gate）都是团队共识的流程约定。设计上可以选择"程序强制"（如不签字就不让走下一步）还是"流程约定"（靠团队共识和可追溯性约束）。

## 决策

- 不设技术强制。任何人硬跳过也不会被程序阻拦
- 明确告知团队：跳过 = 破坏交付可追溯性
- 其中两步本质是线下动作，AI 只能辅助不能代替：
  1. **客户签字**（client-gate 入口 / acceptance-gate 出口）：AI 生成待签件、检测是否已签
  2. **eval Tier2 专家标注**：专家不到位则挂起
- 范围变更仍走 client-gate 重签；BMAD 的 correct-course 等重流程属于按需能力，不作为每个项目的强制步骤

## 后果

- 正面：保持灵活性，不因技术锁阻碍应急响应
- 正面：对诚实团队足够，对不诚实团队也拦不住
- 代价：需要团队文化配合，新人可能跳过流程而不自知
- 缓解：在每个 SKILL.md 的"关卡纪律"段显式说明
